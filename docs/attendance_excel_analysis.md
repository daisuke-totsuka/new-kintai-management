## VBAで確定している業務ロジック

- カレンダーは `set_calendar` で生成する。
- 年は1から3000、月は1から12のみ許容する。根拠: Module1 20-54。
- 祝日が日曜の場合は翌日を振替休日にする。根拠: Module1 90-124。
- 1月、10月は第2月曜、7月、9月は第3月曜をハッピーマンデーとして扱う。根拠: Module1 60-87。
- 実働時間はExcel数式で算出し、VBAで5分単位エラー、15分単位警告を行う。根拠: Module1 385-398。
- 入力チェック正常終了時、`Cells(3,17)`に`完了`または`完了*`を設定する。根拠: Module1 1558-1563。
- 深夜勤務または総実働が`平日数*8+45`を超える場合は`完了*`になる。根拠: Module1 1558-1563。
- 振休警告がある場合は`警告`になる。根拠: Module1 1535-1568。
- 印刷は入力エラーフラグ`A40`が空の場合のみ可能。根拠: Module1 1603-1609。

## Web反映時の確定仕様

- 勤務実績画面は対象月の日数のみ表示する。
- 作業内容はExcel同様1項目とする。
- 通常勤務時間は別画面で編集し、勤務実績画面では参照のみとする。
- エラーはMsgBoxではなく、エラー一覧とセル強調で表示する。
- Excel VBA相当の業務ロジックはBackendへ集約する。
- Frontendは入力支援に限定する。
- Backendを業務ルールの正とする。
- 保存単位は月単位とし、入力形式エラーがある場合は保存しない。
- 排他制御は `updated_at` による楽観的排他制御とする。
- dirty管理はFrontendで行い、変更行のみAPI送信する。
