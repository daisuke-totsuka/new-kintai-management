# 勤務実績Web仕様書

## 位置づけ

本仕様は、`docs/9999_勤務表yyyymm（名前）_xxxxx.xlsm` の `勤務実績（月間）`、`祝日表`、`データ`、`エラーメッセージ一覧`、VBA `Module1`、および解析済み設計書を正として、勤務実績機能のWeb仕様を整理する。

本更新は設計書のみであり、実装、ソースコード変更、DB変更、API変更、コミット、Pushは行わない。

詳細仕様は以下を正とする。

- 画面項目: `docs/attendance_screen_items.md`
- 入力チェック: `docs/attendance_validation_rules.md`
- エラーコード: `docs/attendance_error_codes.md`
- UIルール: `docs/attendance_ui_guideline.md`
- VBA-Web対応: `docs/attendance_vba_mapping.md`

## 確定仕様

|分類|仕様|
|---|---|
|表示日数|対象月の日数のみ表示する。2月30日など存在しない日は表示しない|
|作業内容|Excel同様、1日1項目として扱う。ExcelのK:P結合セル相当|
|通常勤務時間|勤務実績画面では参照のみ。編集は通常勤務時間設定画面で行う|
|通常勤務|勤務区分ブランクで表現する。通常勤務用のコード値は持たず、画面初期表示もブランクとする|
|土日祝日の勤務区分|土日祝日は勤務時間だけ入力されていても勤務区分を必須にしない。勤務区分ブランクのまま登録可能とする|
|エラー表示|エラー一覧とセル強調表示を併用する|
|業務ロジック|Excel VBA相当ロジックをBackendへ集約する|
|Frontend責務|入力支援、dirty管理、セル強調、エラー一覧表示、印刷表示|
|Backend責務|入力形式の再検証、E001-E020、集計、深夜勤務、状態遷移、排他制御|
|正本|業務ルールはBackendを正とする|

## 画面仕様

画面は、ヘッダ、社員情報、対象年月、通常勤務時間、勤務実績一覧、集計欄、エラー一覧、ボタンで構成する。

|領域|Web仕様|Excel対応|
|---|---|---|
|ヘッダ|画面名、状態、保存・提出等の操作を表示|勤務実績（月間）!A1:Q3、Cells(3,17)|
|社員情報|社員番号、氏名、作業場所、所属を表示|祝日表!C2:F2、L2|
|対象年月|年/月を選択し月次データを取得|祝日表!A2:B2|
|通常勤務時間|参照のみ。編集不可|勤務実績（月間）!A43:G44|
|勤務実績一覧|対象月の日数分だけ行表示|勤務実績（月間）!A7:S37|
|集計欄|Backend集計結果を表示|勤務実績（月間）!B38:P39|
|エラー一覧|提出不可時のE001-E020と警告を表示|エラーメッセージ一覧、VBA MsgBox|
|ボタン|保存、提出、編集再開、印刷、合計印刷|Excelボタン割当マクロ|

## 入力項目

日別入力項目は以下とする。詳細は `attendance_screen_items.md` を参照する。

|項目|入力/表示|備考|
|---|---|---|
|出勤日、曜日|表示|対象月の日数から自動生成|
|始業、終業|入力|HH:mm。Backendで再検証|
|休憩|入力|分単位、0以上整数|
|実働|表示|Backend算出。Excel H:I相当|
|勤務区分|入力|Excel X44:X56相当のマスタから選択。ブランクは通常勤務として扱う|
|作業内容|入力|Excel同様1項目|
|遅刻早退時間|入力|0.5単位|
|深夜勤務時間|表示|Backend算出|

## バリデーション仕様

|タイミング|実施内容|正本|
|---|---|---|
|入力時|形式チェック、選択肢制御、作業内容未入力等の補助表示|Frontend補助|
|保存時|入力形式エラー、updated_at、保存可能状態、変更行整合性|Backend正|
|提出時|入力形式、Excel VBA相当E001-E020、集計、深夜勤務、完了表示|Backend正|

提出時はExcel VBA相当のE001-E020を実施する。
E009は休日（土日・祝日等）に勤務区分「欠勤」を指定した場合にBackendで発生させる。Excel `エラーメッセージ一覧` シートにE009定義が存在しないため、Web標準メッセージとして「xx日は休日のため、欠勤を指定できません。」を採用する。
E010は欠勤以外を含む、休日に使用不可の勤務区分を指定した場合の汎用的な休日区分不整合として扱い、Excel定義の「xx日は休日です。」を維持する。
E012はVBA上の有効判定が未検出のため、推測で条件を追加しない。

## 保存仕様

|項目|仕様|
|---|---|
|保存単位|月単位|
|入力形式エラーがある場合|保存しない|
|保存成功|成功メッセージを表示し、dirty=false|
|対象月変更|dirty=trueなら確認ダイアログを表示する。ボタンは「保存して変更」「キャンセル」の2つのみとする|
|保存して変更|変更前月の保存に成功した場合のみ対象月を切り替える。保存失敗時は対象月を変更しない|
|提出|dirty=trueなら保存成功後に提出|
|dirty解除|保存成功、提出成功|
|日別レコード削除|変更行の全入力項目がブランクの場合のみDELETE対象とする|

Frontendはdirtyを管理し、変更行のみAPI送信する。変更なし行は送信しない。変更行について、始業、終業、休憩、勤務区分、作業内容、遅刻早退時間のすべてがブランクの場合はDELETE指定とし、それ以外は保存対象として送信する。Backendは送信された差分をもとに、新規はINSERT、既存変更はUPDATE、全入力項目ブランクはDELETEを実施する。

## 排他制御

`updated_at` による楽観的排他制御を行う。

|ケース|仕様|
|---|---|
|updated_at一致|保存または提出を継続|
|updated_at不一致|排他エラーを返す|
|排他エラー時|入力内容を保持する|
|最新データ取得|Backendから最新データを取得する|
|差分表示|最新データとの差分セルのみ黄色表示する|
|再編集|差分確認後、再編集可能にする|

## 状態仕様

|状態|編集可否|主な操作|
|---|---|---|
|draft|可|保存、提出|
|validated|不可|提出、編集再開、印刷、合計印刷|
|submitted|不可|編集再開、印刷、合計印刷|
|approved|不可|印刷、合計印刷|
|confirmed|不可|印刷、合計印刷|

approved/confirmedで編集再開を不可とする点は、確定済み状態として扱うWeb設計上の推測を含む。承認ワークフローの詳細が確定した場合は見直す。

## 印刷仕様

- 印刷はExcel `print_monthly` 相当の月報印刷とする。
- 合計印刷はExcel `print_total_only` 相当の集計欄印刷とする。
- Excelでは `A40` が空の場合のみ印刷可能であるため、WebではBackend算出の `printable=true` を印刷可否の正とする。
- 週報、交通費、業務請求明細、経費請求系マクロは今回の勤務実績画面の対象外とする。
